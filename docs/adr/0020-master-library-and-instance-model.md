# ADR-0020：对话主库（中心化共享）与实例模型

## 状态

Accepted，2026-08-22。依赖 ADR-0018（红线解除）。2026-08-23 修订决策 4（默认单开 → 并行多开），依据 `.scratch/p2-2-instance-experiments/REPORT.md` 定胜负实验。2026-08-28 修订决策 6（blob 加密格式已完全逆向，保活机制确立），依据 `.scratch/checkin-http/05-签到HTTP直连与设备规则全流程复现手册-20260820.md` §3.2-3.5 与 `.scratch/blob-rewrite-probe/report.md` C0 实测。**2026-08-31 部分被 ADR-0021 取代**：主库改为官方目录绑定 + 记录单一归属当前账号模型；决策 1 的阶段 A/B 划分与决策 3 的「收入/返还」语义废止（记录改归属随行，不再跨库复制）；决策 4/5/6 保留。

## 背景

TRAE Work CN 各账号对话记录互相隔离（每账号独立 data_dir 内的 SQLCipher 库）。用户核心需求：所有账号共用一套规定的历史对话记录，消除隔离。技术事实：TRAE 只读取自己 data_dir 内的数据库，不存在重定向配置；因此"共用"只能通过目录切换或数据复制实现。用户初步构想（主库 + 各账号分类区 + 收入/返还 + 模式开关）经 grill 确认如下。完整决策过程见 `docs/DECISIONS-20260822-GRILL.md` D3/D4/D7。

## 决策

1. **主库机制：目录级切换（方式一），分两阶段实施**：
   - 阶段 A（= 主库原语）：会话级读取与跨库复制能力——读取各账号 TRAE 库（复用 raw key 与 SQLCipher 导出契约，见 `docs/TECHNICAL_BASELINE.md`）、App 内统一阅览全部账号历史、会话级"收入主库 / 返还账号"。此阶段产物独立可用（App 内主库形态），也是失败退路。
   - 阶段 B（= 主库模式）：主库 = 一个专用 data_dir。开启时把当前账号登录凭据注入主库目录，以主库目录启动 TRAE——任何账号登录都看到并操作同一套历史；关闭后各账号正常使用自己的 data_dir。
2. **纯本地**：不考虑云端、不做云同步对接；主库数据只存本机。
3. **语义约定**：主库开启期间产生的新对话归主库；关闭后账号独立历史中没有它们，需手动"返还"到目标账号（含"自定义账号"目标）。返还支持原账号与任意指定账号。
4. **实例模型（2026-08-23 修订：默认单开 → 并行多开）**：账号列表点账号 = 启动/聚焦该账号实例，**不关闭已运行实例**；实例按 `--user-data-dir` 隔离目录并行运行（实验证实 per-directory 锁、无全局互斥）；**主库模式开启时强制单实例**（SQLite 单写者约束，主库 data_dir 不允许并行多写）。修订依据：用户明确要求不中断正在使用的实例 + 并行实验证据（见状态行报告）。
5. **data_dir 保留为本地状态隔离单元**（登录态、缓存、会话互不踩踏）；机器级风控隔离不依赖 data_dir（服务端设备身份由硬件指纹派生，data_dir 从未隐藏机器身份，已实证；签到层隔离由 ADR-0019 虚拟设备承担）。
6. 阶段 B 的两个已知技术风险，进入 Phase 4 后先小规模实测再全量实现：凭据在主库目录内互换（A 换 B）TRAE 是否无感接受；实例启动对注入凭据的刷新时机。**2026-08-23 部分提前验证**：登录 blob（`iCubeAuthInfo`，"tc"0x0510 加密格式）的密钥为机器级，跨 data_dir 复制 `User\globalStorage` + `machineid` 即完成登录态迁移，TRAE 无感接受（实验见状态行报告）；但 blob 无法由 App 的 OAuth token 直接构造，阶段 B 的注入仍需 TRAE 原生登录产出 blob 或逆向其加密格式。

## 后果

- 用户在 TRAE 内获得完整共用体验（任何账号同一套历史）；阶段 A 先行降低整体风险，且其阅览/搬运能力独立有价值。
- 主库模式与多开互斥需要 UI 明确引导；换账号需重启 TRAE 实例（主库模式下）。
- 会话跨库复制涉及消息树 ID 重写与附件引用处理，是阶段 A 的主要工程难点。
- 主库 data_dir 本身成为重要用户数据，纳入手动备份入口的保护对象。
- 并行多开（2026-08-23 修订后果）：P2-2 起账号实例可同时运行，App 需展示各实例运行状态；用户手动打开的 TRAE（主目录）与 App 管理实例并存，互不干扰。
