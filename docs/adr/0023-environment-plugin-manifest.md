# ADR-0023：环境插件清单模型（切号同步基线）

## 状态

Accepted，2026-08-31。决策来源 grill-with-docs 会话（2026-08-31，主库详情页设计）。协议事实见 `docs/TECHNICAL_BASELINE.md` 插件云端 API 章节（plugin_sync_probe 真机闭环）。**2026-09-04 修订：决策 2 的对账确认语义（+N/-M 弹层、新账号二选一）已被 ADR-0026 取代**（改为静默应用 + 含移除时单次确认）；其余决策继续有效。

## 背景

切号后插件市场为空的根因已实证：安装状态是账号维度云端数据的本地缓存，TRAE 重启后按目标账号云端列表调和本地安装（云端没有的触发卸载）。P5-6 已落地切号第 4.5 步「云端插件预同步」（fail-soft 增量转发）。用户进一步要求：把插件管理移入工具（环境详情页插件 tab），使「账号无关内容」绑定在环境上，后续 V2 副库直接复用。

核心分歧：插件绑定的事实源放账号云端还是环境清单。纯账号云端模型无法表达「移除随行」（只增不减，卸载操作永不跨账号传播）；纯清单审批模型会回滚用户在 TRAE 内的手动操作。

## 决策

1. **环境持有插件清单（绑定基线）**，首次启用从当前账号云端导入。清单角色 = 同步基线 + 恢复依据，**不是审批闸门**。
2. **切号对账 = 吸收后应用**：先吸收当前账号云端的增删差异进清单（用户在 TRAE 的手动操作视为真实意图），弹层以 `+N / -M` 形式一次确认；确认后把清单应用到目标账号（缺的装上、多的卸掉），移除部分在确认中单列（破坏性操作红线）。登录全新账号做切换目标时提供「按环境清单应用 / 以该账号现状为准」选择。
3. **工具内插件管理即时修改当前账号云端**（装/卸直连 API），同时更新环境清单；无差异时切号静默直过，不加确认步骤。
4. **差异识别时机 = 用户自然触发**（打开插件 tab / 切号弹层），不做后台轮询。
5. **失败语义 fail-soft**：同步失败只影响插件市场显示（可手动重装），绝不阻断切号主流程。

## 后果

- 插件 tab 的「浏览市场 + 安装」与「移除随行」两大能力前提均于 2026-08-31 探测闭环（api_gap_probe 实测：市场目录 API 200/`data.plugins`；云端卸载 DELETE code 0 + 重装往返无损，`builtin:` 前缀条目为客户端内置不可卸载需跳过）——原降级预案（退化为只管理已装清单 / 移除不随行）不再触发。协议事实见 `docs/TECHNICAL_BASELINE.md`。
- 环境清单是工具自有状态，与环境注册表同存（存储根）；V2 副库各自持清单，语义不变。
- TRAE 内手动装/卸在下次触发对账时纳入，中间态两边不一致是可接受的最终一致窗口。
