# ADR-0022：会话级归档通道（hidden_status 原生枚举借用）

## 状态

Accepted，2026-08-31。决策来源 grill-with-docs 会话（2026-08-31，主库详情页设计）+ 真机实验闭环（`.scratch/history-u6/w0-probe/` hidden_status_probe / batch_hide_default）。**2026-09-12 修订**：决策 1 中“归档会话切号随行不受影响”被 ADR-0028 取代；本 ADR 的 `hidden_status` 通道、归档抽屉和恢复归位继续有效，归档/恢复的批量提交边界由 ADR-0028 定义；项目归档、项目恢复和项目合并语义由 ADR-0028 定义。

## 背景

主库详情页对话列表需要「不想看到但不想删除」的会话收纳能力（口语：出库/入库）。候选实现有三：改写 `project.user_id`（TRAE 严格按 user_id 过滤可见性，但粒度是项目级且与主库体检/收编语义冲突）、`chat_session.deleted_at`（删除语义，有被 TRAE 清除机制回收的风险）、`chat_session.hidden_status`（TRAE 自己的会话级显示开关）。

真机实验（2026-08-31）实证：

- 会话列表过滤是**排除式枚举白名单**：只认 `scheduled_task` / `voice_discussion` 两个原生值。自造值 `traesync_archive` 写入存活、重启不被回写、但列表不隐藏。
- 借用 `voice_discussion`：25 个会话隐藏/恢复全部生效，重启后「默认」分组整体消失，新会话再建分组后恢复的会话自动并入（侧栏按 work_mode 类型聚合，非按 project 行）。
- 副作用排查：前端全部消费点为遥测上报与插件推荐过滤（被隐藏会话跳过推荐），无 UI 路由消费该值；库内原生 `voice_discussion` 会话存世一个月无异常视图出现。
- 其他字段不可用：`deleted_at` 删除语义、`is_pinned` 置顶、`extra`/`context` 黑盒 JSON。

## 决策

1. **会话归档 = 写 `hidden_status = 'voice_discussion'`**；恢复 = 还原为 NULL。粒度是会话级，不改变记录归属；是否参与切号由 ADR-0028 的冻结边界决定，归档会话不再随切号交接。
2. **归档抽屉是对话列表 tab 内的子视图**（非独立平级 tab），按「模式（code/work）→ 分组 → 会话」层级收纳，保留原位信息。
3. **恢复即归位**：不做分组映射表——侧栏原生聚合保证恢复会话并入当前同类型分组。
4. **批量操作走 Gmail 式选择态**：浏览态无勾选框，进入选择态后浮出批量栏（归档/恢复/删除）；删除是真实删除（消息+会话+空壳项目行），列明规模单次确认。
5. **分组合并定位为历史遗留清理工具**（任意选组合并为底层操作 + 同名合并快捷入口），非归档流程依赖；执行走关实例事务。

## 后果

- 归档语义借用语音讨论枚举：若 TRAE 未来版本改变白名单或增加语音历史视图，需重新验证；验证脚本已在探针工程沉淀。
- 归档状态与 TRAE 原生隐藏共用同一值空间：原生语音会话在我们归档视图中会出现（按 hidden_status='voice_discussion' 检索不区分来源），展示时按原位层级自然呈现，可接受。
- 术语：会话侧「已归档」与账号侧归档（U-6 W4 三态）同名不同物，UI 文案落地时按上下文区分或改用「已隐藏」等别称，实现期定。
