# ADR-0018：数据红线解除与新的数据安全约定

## 状态

Accepted，2026-08-22。取代原 Gate 资格体系与强制备份执行条件（原 ADR-0009/0011，文件已清理），以及原 AGENTS.md 中"不写真实活动数据库""强制双备份、完整验证、崩溃协调"的全部红线条款。原 ADR-0014 第 6 条的数据库写入禁令由本 ADR 解除（其余条款已并入 ADR-0019）。注：后果中提及的主库模式「收入/返还」语义已随 ADR-0020 被 ADR-0021 废止，本 ADR 红线解除决策本身不受影响。**2026-09-02 修订**：决策 3 的备份铁律按用户主动决策修订——主库备份允许按用户配置的保留策略自动裁剪（P5-9，默认保留最近 5 份、可关闭；关闭时回退为不自动删除），用户历史、快照、失败证据的不自动删不变。

## 背景

项目立项时按"单账号谨慎试点"定位建立了数据红线：真实 TRAE 数据库只读、写入需强制双备份/完整验证/崩溃协调/用户确认，并以 Gate 证据体系控制能力开放节奏。2026-08-22 与用户确认项目定位变更为**个人使用的多账号日常管理工作台**，四个核心需求（账号保存、对话跨账号共享、直连签到、账号切换）全部要求直接操作真实数据；重流程门禁与单人工具的定位不匹配，用户明确指示红线全部解除，仅保留手动备份入口。完整决策过程见 `docs/DECISIONS-20260822-GRILL.md` D1/D2。

## 决策

1. 允许直接读写 TRAE 真实数据：包括 TRAE Work CN 活动数据库（SQLite/SQLCipher）、认证存储与全部 HTTP API（OAuth 登录、ExchangeToken、签到、账号信息）。
2. 废止强制流程：双备份、完整验证矩阵、崩溃协调、Gate 证据链不再作为任何操作的前置条件；`evidence/gates/` 已有产出归档停用，不再新增。
3. 新的数据安全约定：
   - App 提供手动备份入口：用户自选备份位置、内容（账号凭据/历史库/主库）、时机；
   - 破坏性批量操作（删除、覆盖、迁移）执行前单次确认；
   - 铁律（2026-09-02 修订）：工具不得自动删除用户历史、快照或失败证据；主库备份（`.switch-bak-*`）例外——按用户配置的保留策略自动裁剪（P5-9：默认保留最近 5 份、设置页可调可关闭，关闭时完全不自动删除；裁剪仅删备份链文件，附属件连带）。
4. 工程纪律保留但降级为内部质量要求：原子写、写后读校验、测试覆盖照旧执行，不构成流程门禁，不产生证据义务。
5. 未来若项目定位变化（如多人使用、对外发布），数据安全管控按新决策重新引入，本 ADR 届时被新 ADR 取代。

## 后果

- 主库模式（ADR-0020）的目录切换、凭据注入、会话收入/返还不再被流程阻塞，可按正常开发节奏实现。
- 数据安全责任从流程保障转移到用户手动备份习惯；误操作风险由单次确认兜底，深级恢复能力减弱——这是用户知情并接受的取舍。
- 历史 Gate 相关代码（evidence 收集、资格判定）成为死代码，随模块改造逐步移除，不做一次性大删除。
- 旧规范文档（GATE_PLAN.md、IMPLEMENTATION_SPEC.md 等）与旧 ADR-0001~0017 已于 2026-08-22 彻底清理，git 历史可查。
