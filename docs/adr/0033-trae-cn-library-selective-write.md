# ADR-0033：Trae CN 库选择性写边界

## 状态

Accepted，2026-09-29。修订 ADR-0032 决策 5 的「CN 主库只读浏览，写入类能力不随只读浏览开放」结论——从「全只读」升级为「选择性写」；ADR-0032 其余决策（三态渲染、探针门禁、文案单一事实源）继续有效。依赖 ADR-0021（单一归属原语）、ADR-0028（归档通道）。

## 背景

用户需求：CN 库（类 VS Code 按项目分类）支持「以项目为整体单位的跨账号转移」与「会话归档」，即把同目录下各账号的对话归并到目标账号。这要求写 CN 库，触碰 ADR-0032 只读边界。

实测证据（2026-09-28/29）：
- schema 同构：CN 库与 Work 主库 61 表同名同列族，`chat_session` 无 user_id（归属唯一来源=project.user_id 经 JOIN），项目=目录成立（`project.absolute_path`，同目录跨账号因 `UNIQUE(biz_project_id, user_id)` 天然多行）。
- **交接原语已被 CN 客户端真实容忍**：09-28 晚三次 `master_handover_manual` 真实交接（用户授权，备份先行+归属改写+换腿+合并，生产同款 `handover_master_records_from_merge_with_progress`），官方客户端在其后持续正常工作（WAL 活跃至 09-29），库读取探针结构健康，无复活/损坏迹象。
- 未验证项：官方客户端**重启后**云端镜像（server_history_info 本地缓存 11778 行）是否覆盖改动；**归档写**（hidden_status）在 CN 尚未动过。

## 决策

1. **选择性写**：CN 库开放两类写——① 项目归并（同目录跨账号行合并到目标账号：空镜像清理+会话并入+session_project 改挂+换腿重写，复用 Work 收编原语按目录过滤收窄）；② 会话归档/恢复（hidden_status 通道，同 ADR-0022）。**删除会话/合并项目/清理空壳仍拒绝**（`library_read_only` 保留于未开放写）。
2. **前置门禁（三步真机验收，不过则回退只读）**：① 应用内归并一次 + 官方客户端验证记录正常；② 重启官方客户端验证不复活；③ 签到 claim 一次 + 额度核对（属 ADR-0032 探针门禁的签到实装，共用验收窗口）。
3. **无路径 empty 项目不参与目录匹配**（不可被转移；清理另走清理功能，若未来开放）。
4. **收编入口挂 CN 详情页**；归档入口复用 LibrarySessionsPanel 既有交互（readOnly 标志按库能力开关）。
5. CN 库不设「当前账号实测」语义（注册表权威，ADR-0025 分化不变）；归并目标=当前指针账号。

## 后果

- 正面：CN 库能力与 Work 主库对齐（转移/归档），多账号 CN 使用场景闭环。
- 负面/风险：官方云端镜像回写容忍未长期验证——以三步验收为门禁，验收通过后仍保留「备份先行」（复用家族铁律）与接力台账证据；如验收失败回退只读（错误码回 `library_read_only`）。
- 可逆性：写能力为代码层开关（能力判定函数），可回退；已写数据靠备份链恢复。
- 检查路径：单测（归并变体/冲突分支/守卫）、真机三步验收报告落档 `.scratch/`。
- 责任：用户裁决 + 本地检查。
