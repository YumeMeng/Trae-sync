# ADR-0032：产品化界面适配与能力三态

## 状态

Accepted，2026-09-28。局部取代 ADR-0029 决策 4（未适配能力不进导航）与决策 9（Trae CN 不显示签到入口）的「整页隐藏」结论，以及 ADR-0030 决策 5 的「当前不开放签到和额度」结论；ADR-0029 其余边界（凭据/数据库/设备隔离、验收状态流）与 ADR-0030 的协议验收门禁全部继续有效。依赖 ADR-0025（Library 抽象）、ADR-0029（多产品边界）。

> **⚠️ 局部修订标注（2026-09-29）**：决策 5 的「CN 主库只读浏览……写入类能力不随本决策开放」已被 **ADR-0033** 的「选择性写（项目归并+归档/恢复）」修订；本 ADR 其余决策继续有效。

## 背景

Trae Work CN 与 Trae CN 是同一公司、同一账号体系的两个应用，多数机制相同。2026-09-28 grill 会话（六议题 28 项定案，记录 `.scratch/grill-session-20260928-production-refinement.md`）中用户裁定：界面层应统一——「页面本体一致、仅内容不同」，差异只允许来自内核（数据源、通道、能力），不接受当前「整页按产品开关」的残缺形态。

原 ADR-0029 的「未适配能力不进导航」是为防「点击后失败」的假入口；本 ADR 用更精细的三态渲染保留诚实 UI，同时消除整页缺失带来的产品间体验断裂。

## 决策

1. **导航五页全产品开放**：总览、账号、签到、环境、设置对所有产品开放，页面本体一致，由共享组件承载；主库详情入口随环境能力开放。页面差异只来自产品注册表（`displayName`、能力清单）与适配器，不允许按 productId 整页分支。
2. **区块能力三态渲染**：每个功能区块按当前产品能力呈现三态之一——
   - `ready`：能力已适配，渲染真实数据与操作；
   - `pending`：能力在途（尚未适配），渲染诚实说明（如「该能力适配中」），不渲染操作；
   - `absent`：协议事实不存在，渲染「该产品无此能力」。
   分支判定依据产品能力清单与探针结论，不在组件内散落 productId 判断。
3. **执行顺序铁律**：Work CN 先收尾（本 Phase P11-1~P11-5），Trae CN 适配（P11-6）其后；共性改动落在适配层与共享组件。
4. **Trae CN 签到探针门禁**：开放签到区块前必须先做只读协议探针（status 类查询先行，不消耗签到配额、不发 claim），探针结论落档 `.scratch/`；有端点则实装，无端点则永久显示 `absent` 态（「该产品无签到」）。禁止跳过探针直接实现。
5. **Trae CN 主库只读浏览**：复用 ADR-0025 的 Library 抽象与 `LibrarySessionsPanel` 的 `libraryId` 边界接入 Trae CN 数据根只读视图；写入类能力（归档/收编/删除）不随本决策开放，需另行评估。
6. **界面文案单一事实源**：产品名等界面文案取自产品注册表 `displayName`，不逐处硬编码。

## 后果

- 正面：产品间体验一致；新增产品只需注册表 + 适配器 + 探针；诚实 UI 从「藏」升级为「说明」。
- 负面：共享组件增加三态分支复杂度；未适配区块占用导航位（用诚实说明缓解）。
- 可逆性：三态渲染为 UI 层改动，可回退；探针结论是协议事实，不可逆但只增不改。
- 检查路径：vitest 能力三态用例（每产品每区块状态断言）；`cargo test --workspace` 与前端全量回归。
- 责任：用户裁决 + 本地检查（单测/组件测试/e2e）。
