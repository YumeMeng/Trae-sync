# ADR-0026：插件同步策略（全实时 + 分级确认）

## 状态

Accepted，2026-09-04。决策来源 grill 会话（2026-09-03，G23 议题）。**本 ADR 取代 ADR-0023 决策 2 的对账确认语义**（「+N/-M 弹层一次确认」「登录新账号二选一」）；ADR-0023 其余决策（环境持清单、工具内即时管理、差异识别用户触发、fail-soft）继续有效。ADR-0023 状态行已同步标注。

## 背景

P5-8b 落地后插件 tab 出现常驻「对账条」（plugin-drift 提示）与切号弹层的差异确认层，操作链路长：装一个插件要过确认、切一次号要过对账弹层。插件是低风险内容（装/卸云端 API 均已探针闭环，重装往返无损），确认成本远高于误操作成本。

## 决策

1. **新增 = 全实时零确认**：安装即时应用到当前账号云端 + 更新环境清单（沿用 ADR-0023 决策 3），无任何确认弹层。
2. **移除 = 单次确认 + 全账号传播**：卸载确认文案列明影响面（「将同时从 N 个账号移除」），确认后当前账号云端卸载 + 清单移除 + 其他已知账号云端卸载（逐账号尽力执行，fail-soft）。卸载确认同时提示「移除后切换账号不再带走该插件」。
3. **切号 = 静默应用对账**：切换时差异（装/卸）直达目标账号云端，不再有 +N/-M 确认弹层与「按清单/按现状」二选一；**仅当差异含移除时弹一次确认**（破坏性操作红线，ADR-0018）。
4. **对账条（plugin-drift）移除**：常驻差异提示随静默应用策略自然消失；差异识别仍为用户触发（打开插件 tab / 切号），不做后台轮询。
5. **失败语义不变**：fail-soft，同步失败不阻断切号、不阻断插件管理主流程（ADR-0023 决策 5）。

## 后果

- 插件集合事实源仍是环境清单（ADR-0023 决策 1）；移除的全账号传播使所有已知账号向清单收敛，跨账号插件一致性由工具保证。
- 移除传播需要逐账号云端 API 调用：账号数多时卸载耗时上升，属可接受（用户显式确认过影响面）。
- 「builtin: 前缀条目不可卸载」约束继续跳过（探针实证）。
- 术语按 G4：插件标签「切号保留 / 仅此账号」；卸载确认文案见决策 2。
