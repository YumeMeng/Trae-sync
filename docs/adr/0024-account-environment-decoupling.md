# ADR-0024：账号-环境解耦与登录凭据存档模型

## 状态

Accepted，2026-09-01。部分修订 ADR-0020 决策 4（并行多开的承载形态从「账号专属实例」改为「环境」）。实证依据：E1 最小供体切号实验（`.scratch/minimal-donor-e1/REPORT.md`，2026-09-01，沙箱真机定论）+ 存储根空间盘点（2026-09-01，本 ADR 背景节）。

## 背景

现行架构下每个账号在 `{storage_root}\trae-instances\{profile_id}` 维护一份完整 TRAE 实例目录（可启动的隔离运行环境 + 切号供体）。2026-09-01 空间盘点实证：

- `trae-instances` 共 19.3 GB（7 账号）：其中 5 个账号目录各约 3.5 GB，**98.6% 是 `ModularData/ai-agent/vm/tools` 工具链缓存**（3,467.6 MB/目录）；import 账号另有 1.5 GB 工具链下载暂存（`vm/tools_staging/*.hyperfetch`）；1 个账号（`checkin-66d8f009f598`）从未启动过实例，仅 4 MB 三件套，反而印证了最小形态。
- `environments/master` 3.5 GB：P5-0 时代主库专属目录，ADR-0021 修订主库为官方目录后已退役（`environment_registry.rs` 模块注释明示），仅档案与台账仍存于 `environments/`。
- `snapshots` 3.3 GB：旧历史快照体系（T02-T08 资产），代码引用仍在（`application/history.rs`），调用链死活待查。

E1 实验（沙箱真机）定论：**切号对供体实例目录的唯一消费是 `User/globalStorage/storage.json` 中的登录 blob**——供体目录剥离到三件套（`storage.json` + `state.vscdb` + `machineid`，共 2.7 MB）时，身份互换完成且 TRAE 实启动接受（`[getUserInfo] response success` 服务端验证 + 持续 10 分钟 API 请求 200 OK + 用户肉眼确认登录窗口）。工具链缓存等为 TRAE 运行时派生数据，可删可重建。

用户裁定（2026-09-01 grill）：「启动实例」功能移除——每账号维护完整隔离环境与四大核心需求（账号保存/主库共享/直连签到/账号切换）无交集且空间代价不可接受；以「环境」概念替代：环境与账号为两个独立的多对多关系，账号信息独立保存，签到仅消费账号信息，环境提供账号切换场所。

## 决策

1. **登录凭据存档（供体存档化）**：账号实例目录的职责收缩为「登录凭据存档」——切号供体读取与 U-7 保活写回的全部消费面。目录内三件套（`User/globalStorage/storage.json` + `state.vscdb` + `machineid`）保留；工具链（`vm/tools`）、下载暂存（`vm/tools_staging`）、各类运行缓存（`Cache`/`CachedData`/`Code Cache`/`GPUCache` 等）与日志确认为运行时派生数据，纳入可清理范围。目录路径 `trae-instances\{profile_id}` 与三件套路径不变（保活/切号/供体读取零改动），概念上不再称为「实例目录」。
2. **「启动实例」功能退役**：账号页启动/聚焦账号专属 TRAE 实例的入口与状态轮询移除。并行隔离运行的诉求由「环境」显式承接（见决策 3）——不再隐式为每账号维护一份完整实例，用户按需创建环境。新账号登录态获取走决策 4 的凭据包构造路径（E2 已实证），不再需要任何临时登录采集流程。
3. **环境模型（账号 ↔ 环境多对多）**：环境 = 一个独立 TRAE 数据目录 + 当前登录账号。
   - 主库环境（`env_id=master`）绑定官方目录，默认且不可删除，全部对话记录的唯一承载（ADR-0021）。
   - 副环境为用户自建（`{storage_root}\environments\{env_id}`），结构与官方目录相同，独立于主库。
   - 任意账号可登录到任意环境（凭据互换原语，与主库切号同构）；环境内记录单一归属当前登录账号（ADR-0021 语义泛化到全部环境）。
   - 环境间可并行运行（per-directory 锁，ADR-0020 并行实证）；环境内单实例（SQLite 单写者约束）。
   - V1 不做环境间记录搬运：环境是独立库，记录留在各自环境内。
4. **新账号登录态获取路径（E2 已定胜负：构造成功）**：凭据包（token/refreshToken/过期时间/account_id）+ GetUserInfo 实调响应 + 字段映射表（代码内置静态知识），可直接构造登录 blob 明文——目标环境密钥材料加密写回后 TRAE 接受并通过服务端验证（E2 实验，`.scratch/e2-credential-login/REPORT.md`，2026-09-01 沙箱真机定论：`[updateUserInfo]` 加载构造明文 + `[getUserInfo] response success` + `[LoginStatus] logged in`）。新账号登录到环境零实例目录依赖；决策 2 的一次性登录采集兜底不再需要。切号供体双路径已裁定（2026-09-01 grill）：**凭据包构造优先，存档移植降级**——GetUserInfo 实调不通过或构造自校验失败时绝不写库（E2 纪律），静默降级 E1 存档移植；双路径均失败才报「目标账号凭据不可用」（原 `switch_donor_login_missing` 语义改写，专属实例概念已退役）。单账号存储预算 ≤ 10 MB：凭据包（KB 级）+ 虚拟设备（KB 级）+ 存档三件套（2.7 MB）≈ 3 MB，达标。
5. **账号三能力解耦条文化**（现状固化）：账号保存 = 凭据包 + 虚拟设备 + 登录凭据存档；签到 = 仅消费凭据包与虚拟设备（HTTP 直连，已实现）；登录态注入环境 = 凭据互换（切号/环境登录共用原语）。

## 后果

- **空间回收约 23 GB**：工具链 17 GB + 退役 `environments/master` 3.5 GB + import 暂存 1.5 GB + snapshots 视调用链裁定（至多 3.3 GB）。清理为破坏性批量操作：执行前出逐账号清单与会话数核验（实例库 `chat_session` 实测为空，但执行时重新验证），单次确认（ADR-0018）；备份链、档案、台账、失败证据永不入清理范围（铁律）。
- **ADR-0020 决策 4 修订**：并行多开的承载从「每账号实例」改为「环境」；决策 6 的登录态迁移实验结论保留（种子复制资产继续服务一次性登录采集兜底）。
- **P2-2/P2-3/P2-4 资产部分退役**：启动/聚焦/关闭命令与账号页实例 UI 退役；种子复制（`seed_login_state`）、登录态判定（`instance_login_state`）、进程管理原语（exe 发现/命令行匹配/优雅关闭）保留复用于环境实例与登录采集。
- **U-7 保活不变**：写回路径与进程互斥检查照旧（存档目录无 TRAE 运行，互斥检查自然通过）；存档 blob 不再被 TRAE 启动清理，供体稳定性反而提升（P5-1 已知问题「供体 blob 被陈旧清理」的诱因消除）。
- **snapshots 处置挂起**：`application/history.rs` 引用仍在，需先确认调用链是否为活路径（Phase 5 历史页已改读主库）；孤儿则按孤立资产流程提交用户裁定，不静默删除。
- **环境删除为破坏性操作**：环境内含会话记录时删除需单次确认并列明规模；空环境可直接删。
