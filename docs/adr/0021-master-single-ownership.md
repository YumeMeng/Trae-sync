# ADR-0021：主库记录单一归属模型

## 状态

Accepted，2026-08-31。部分取代 ADR-0020（阶段 A/B 主库模型与「收入/返还」语义废止；并行多开与失败退路等其余决策保留）。2026-09-09 修订（P8-6）：删除 App 独立历史工作区，对话列表仅由主库详情页承载。决策来源 `.scratch/grill-log-20260831-master-ownership.md`（grill-with-docs 会话逐项裁定）。

## 背景

2026-08-31 主库 data_dir 修订为官方目录（`TRAE SOLO CN` 数据目录）后，只读探针实证（`.scratch/master-inspect-20260831/`）：库内并存 5 个账号的记录（`project.user_id` 区分——主力账号 39 项目/78 会话、3 个账号零星记录、1 个 UNIQUE 约束空壳镜像行、0 孤儿行）。这是 Manager 时代与官方登出/登录切号「不转移记录」的遗留状态。用户在此事实下重新审视主库语义：既然主库就是环境内对话的集合，按账号区分记录、以及「加入/脱离主库」类功能都失去意义——记录应永远归属当前登录账号。

## 决策

1. **主库 = 主库环境（官方目录）内全部对话记录的集合**，不是某个账号的内容。库内记录**单一归属当前登录账号**：任何时刻全部记录的 `project.user_id` 指向当前账号；任何账号登录后看到的都是同一套完整历史。
2. **归属随行（切号即归一）**：切号五步事务（P5-1）的交接步骤保证单一归属——切号后库内不存在非当前账号的记录。账号间记录区分因此失去产品意义；TRAE 原生界面即完整记录浏览器。
3. **收编**：不切号场景下把库内非当前账号的记录（含未注册账号的历史遗留）一键归入当前账号。形态为环境页「主库体检」区块：只读展示账号分布（各账号项目/会话数、未注册账号标注）与空壳镜像等异常 + 「归入当前账号」动作，复用 P5-1 交接原语（关实例 → 三件套备份 → 空壳清理 → 归属改写 → 活跃会话换腿 → 校验 → 重启）。
4. **独立历史入口删除（P8-6）**：TRAE 原生已可见全部记录；App 不再提供独立历史工作区，对话列表作为主库详情页的库内模块承载，保留接力轨迹、归档与主库统计能力。
5. **插件不随记录模型走**：插件本体机器级存放（`~\.trae-cn\extensions` 与 `~\.trae-cn\plugins`），切号不动；安装状态为账号维度数据（`state.vscdb` 存在 per-user_id 命名空间键，市场权威状态疑在云端，`--install-extension` CLI 实测不可用）。我方 blob 互换切号不触发登出、不清缓存，插件列表可能保持——列为 P5-2 真机验收观察点，实测后再裁是否需要随行方案。

## 后果

- 记录的「原始作者」信息只存在于接力台账（relay ledger）；其 UI 呈现在主库详情页对话列表的接力 tab 中。
- 收编是破坏性批量操作：执行前单次确认 + 三件套备份（ADR-0018）；非空 UNIQUE 冲突报人工决策（沿用交接原语既有语义）。
- 收编后未注册账号（如探针中的 `…26768`）记录归当前账号；将来该账号 OAuth 注册入册后，切号全量随行语义保证记录不丢失，只是归属随之漂移。
- 探针实证（5 账号分布）是体检区块的第一批真实数据；空壳镜像行在收编与切号中原语级自动清理。
- ADR-0020 的「收入/返还」「主库模式开关」语义废止。
