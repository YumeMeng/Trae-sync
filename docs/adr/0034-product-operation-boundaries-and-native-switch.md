# ADR-0034：产品操作边界、能力验收与真实账号切换

## 背景

现有五层 Rust workspace、Product Adapter、共享页面和 Library 引用已能承载本期适配，不需要另建平台框架。ADR 形成时确认的边界缺口包括：进程匹配可能串产品；Work E1 回退可能消费非目标账号的供体；数据库提交后的失败可能被误报为已回滚；CN 账号切换仅更新工具选择；CN 页面可能触发 Work 设置/签到命令；部分未完成真机验收的能力被展示为可用。当前 WIP 已分离 Settings/Checkin 的产品上下文并加入操作状态门禁，但异步来源、进程调用者和真实验收仍有未完成项；以 `docs/architecture/MODULE_MAP.md` 与 Phase 14 当前状态为准。

## 决策

1. **保留现有分层与最小适配边界。** domain 管纯规则，ports 管外部契约，application 管产品无关用例，infrastructure 管路径、文件、协议、数据库和进程，Tauri 组合根管运行时注入及 IPC。现有根模块的业务编排按任务逐步收敛，不为本次任务整体搬迁。只有存在不同产品行为、需要注入副作用或多个调用者共享规则时才提取边界；不按产品/业务域新增 crate，不新增通用插件框架。未来新增相似产品沿用该边界，本期只实现 Work CN 与 Trae CN。
2. **状态必须对应不同事实。** 工具选中账号、凭据可用状态、官方客户端实测登录账号分别表达。凭据 GetUserInfo 返回目标身份只证明该凭据有效，不证明官方客户端已使用它；写入工具当前指针也不构成真实切换。CN 归并的目标仍可由用户明确选择的账号决定，不依赖客户端实测账号；界面不得把这个选择说成官方客户端已经切换。
3. **操作能力逐项验收。** 在既有能力清单中分开记录操作是否实现、验证范围/证据和本次环境是否满足条件。`ready` 要求该操作已实现、必要验收通过、当前环境可用；`pending` 表示尚未实现或尚待必要验收；`absent` 只用于有事实证明不存在/不支持的操作，不用“没有证据”推断“不支持”。保留五个共享导航页；不支持的操作隐藏，待验收区块诚实说明且不提供普通执行按钮。库浏览可 ready，同时归档/归并 pending；凭据健康与真实切换可以有不同状态。不要新增一个全产品 `verified` 开关掩盖操作差异。
4. **产品边界在后端也必须成立。** 凭据根、账号池、数据根、官方可执行文件、客户端通道与原生登录材料按产品隔离；未知产品/库不能静默回退 Work。前端上下文传递或按钮隐藏不能替代后端校验。全局设置与产品设置明确分开；CN 页面不得读取或修改 Work 的自动签到、备份配置。Work 既有后台调度可以继续独立运行，相关结果须标明来源产品。远程设备列表/退出维持 ADR-0031 的账号级事实与本机保护，不强行拆成产品专属设备列表。
5. **进程与写入前置判断可靠。** 控制进程以已确认的产品可执行文件身份及数据目录共同匹配，保留官方默认启动与既有合法 Work 可执行文件兼容。枚举失败、解析失败、路径/身份不可判定时不得当作“未运行”放行破坏性写入。共享守卫覆盖启动、聚焦、关闭、切换、归档与归并的相关入口；只读观察可独立降级，不能用其宽松结果授权写入。
6. **Work 切换身份先验一致。** E2 与 E1 回退均在写入前核对目标账号、产品与可消费材料。供体为空、身份未知或不匹配时拒绝；断网 E1 仍可使用已确认属于目标账号的存档。规则位于所有相关调用者共享的实际消费边界，覆盖主库切号及环境登录，不仅修 UI 或一条命令。
7. **提交、恢复与启动结果如实表达。** 尽可能将逻辑一致性验证置于数据库事务提交前；提交后必要的重开/持久性验证仍保留。回执区分未提交、已提交且验证成功、已提交但需处理，并分别表达登录材料和客户端启动状态。数据库已提交时禁止只回滚登录材料并声称整体回滚；不得诱导用户盲目重试。备份先行，持久保存跨文件/数据库提交阶段及恢复所需的最小事实（秘密材料保持加密），复用现有原子发布/恢复机制。启动恢复只做可证明安全的本地幂等处理，未知状态保留证据并要求处理，不自动触网、重铸、重复切换或删除证据。不恢复旧 Gate 体系。同产品同数据目录的冲突写操作需要最小串行边界，不能仅依赖按钮 busy。
8. **CN 真实切换独立于历史交接。** 先查明官方 CN 原生认证入口、读取方式、写入原子性、退出重启与实际账号确认方法，再用 CN 自己的已验收凭据在隔离数据目录验证。隔离通过后才接入有备份与产品/账号校验的生产激活。第一切片只完成官方客户端账号激活，不自动归并、归档或交接历史；官方客户端自然写入缓存与工具主动改写历史分别检查。保留已有显式 CN 库操作，但继续受其独立验收门禁约束。验证失败保留原选择/已知官方状态或明确部分完成；不得输出“切换成功”。未经证实的认证文件结构不能按 Work 字段相似性猜写。
9. **CN 签到复用结果判定，不借用 Work 协议假设。** 使用 CN 已确认的通道；遵循 status → 至多一次 claim → status 复核。HTTP 成功或 code=0 不独立证明领取；复核不可用时报告尚未确认，后续只读复核，不自动重复 claim。优先复用已有签到用例/结果类型。CN 自动签到、批量签到不在本期范围。
10. **异步结果与动作保留来源。** 查询结果只更新其产品/库/请求代次对应的视图。产品切换清理详情、选择和草稿展示等旧引用；持久草稿仍按库保存。已提交的动作继续按原上下文完成，不能因页面切换撤销事务或把结果归到新产品；未提交意图不能跨产品执行。
11. **账号页统一共同内容与位置。** 两个产品使用一致的列表与详情骨架：名称/已有备注信息 → 凭据状态、工具选择与官方身份（分别表达）、最近验证及已有有效期 → 常规操作 → 账号级设备区 → 支持时的危险操作 → 默认折叠技术细节。共同操作包括添加/重新授权、健康检测、刷新凭据及本产品已验收的选择/真实切换；同类动作位置、忙碌/失败反馈一致。只映射已有事实与能力，不为对齐而给 CN 增加备注编辑、手机号编辑、额度、删除或自动签到后端。Work 已有备注/手机号编辑、积分与签到信息/设置、凭据有效期、重新登录、设备操作与删除等完整保留为对应能力区。Work 共通数据/动作渐进进入既有账号 view/adapter，复杂主库切换仍委托现有业务编排，不通过大改 DTO 或搬走业务强求同形。
12. **并发账号选择按较新的有效意图决胜。** Trae CN OAuth begin 成功后登记选择意图；显式切号只有在账号档案和本产品凭据均验证成功后才登记，因此无效 profile 不会使较早的有效操作失去资格。以意图持久登记顺序为准，OAuth 回调仅在其代次仍最新时发布当前账号指针；被较新意图取代时，账号与凭据仍正常保存，当前指针保留较新选择。已登记的 OAuth 意图若之后取消或登录失败，不改变当前指针，也不撤销该意图或恢复更早的待完成操作；这样旧操作不会在较新操作失败后迟到生效。登录成功不表示它一定成为当前工具账号。选择代次与指针在同一原子文件中发布，旧格式文件缺少代次时按初始代次读取。此规则仅约束 Trae Sync 工具选中账号，不代表或触发官方客户端身份切换；账号档案与凭据包跨文件恢复仍由 P14-5a/5b 负责。

## 实施与验收

- 先修能力真实性和产品边界，再修 Work 身份/提交安全；此后推进 CN 协议校准、原生切换及独立真实验收。具体依赖、当前状态与测试见 Phase 14，不重跑已经完成的 R0–R3 架构搬迁。
- 使用现有 Rust 注入边界、合成 SQLCipher 数据库、Vitest 延迟 promise/IPC 断言、Playwright 页面流程。mock E2E 不算真实 Tauri、官方客户端或网络验收。
- 合成失败注入至少覆盖身份不匹配、枚举未知、备份失败、提交前失败、提交后验证失败、启动失败和同目录并发；断言实际残留状态、回执与证据一致。
- 同目录有未解决的提交/恢复状态时，后续破坏性操作先拒绝，不能覆盖原记录。恢复仍需的唯一材料作为恢复/失败证据保留，不因普通旧主库备份链裁剪而丢失；已收口的主库备份继续按用户现行策略保留。
- 生产验收是操作级事实：CN 原生切换要独立确认官方身份及重启保持；CN 归并/归档要验证官方可见结果及重启不复活；签到要复核状态与额度。既有 P13-4 共用验收窗口可延续，但签到失败不抹除已完成的库只读证据，库写未验收也不能借签到通过放行。
- 真实破坏性操作按 ADR-0018 在执行点单次确认，明确产品、目标和备份，不能被本 ADR 或测试按钮静默绕过。本次总体审核已返回，用户已授权实施；按 Phase 14 持续分片推进，具体问题按需向审查会话询问，无需逐片重复整体审批。

## 不做

不实现其他产品、跨产品登录/历史合并、CN 自动历史交接、CN 自动/批量签到、Windows 后台任务、插件入口搬家、摘要缓存重构或无引用代码的大删除。24 个前端无直接引用命令先按内部入口/fixture/占位/维护能力/替代 API 分类，只有本次明确退役且已核实调用者的入口才清理。

CN 健康检测 2/2、主库读取及一次同设备凭据换发已有有效实测；一次换发不等于重启恢复。CN 签到 claim、应用内归档/归并与重启、真实原生账号切换仍未完成当前操作的正式验收。详细证据位置及限制见模块矩阵。决定接受不等于代码完成或真机验收完成。
