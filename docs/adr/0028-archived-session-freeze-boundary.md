# ADR-0028：归档会话冻结与账号切换边界

## 状态

Accepted，2026-09-12。取代 ADR-0022 决策 1 中“归档会话切号随行”的语义，并补充 ADR-0021 对归档会话的适用边界；ADR-0022 的 `hidden_status` 通道、归档抽屉和恢复归位语义继续有效。

## 决策

1. 主库继续保留全部会话与项目分类，但分为两类：正常会话和主库冻结内容。
2. 正常会话随账号切换交接，继续执行现有的记录归属更新、会话身份换腿、完整性校验和接力台账记录。
3. 归档会话属于主库冻结内容。账号切换时不得把它们纳入交接候选，不得改写会话/消息身份，不得为其生成接力台账，也不得为其执行逐会话迁移进度或正文校验；它们继续留在数据库和归档视图中。
4. 取消归档后，会话重新纳入当前登录账号的正常会话范围。取消归档不得静默造成“已恢复但找不到”；若不能安全地即时完成并验证，必须显示待同步状态，并提供明确的刷新动作，由工具控制关闭、更新、重启和结果回执。
5. 归档与取消归档先形成一批待提交设置，界面可以连续编辑并即时反映计划状态，但不为单条会话写库或重启 TRAE。待提交设置持久保存为归档变更草稿；用户主动应用时，整批变更在一次数据库事务和一次必要的实例更新中提交；提交失败保留草稿，禁止静默丢失或留下无法解释的半同步状态。
6. 同一项目混合正常与归档会话时不拆分项目：正常会话决定项目是否参与账号交接，归档会话保留原会话/消息身份与内容；项目内全部会话归档时，项目本身也不参与账号交接，归档视图仍可跨账号显示。
7. 切号性能以“归档数量基本不增加耗时”为硬边界：归档会话不得进入交接候选、扫描、写入、校验、台账或进度；正常会话采用集合级读取与校验，约 100 个正常会话的本机切号目标为十秒级，而非分钟级。
8. 归档变更统一提交采用“预检 → 关闭实例 → 单事务更新 → 重启并验证”的边界：预检或关闭失败时不得改库；事务失败时全部回滚并保留草稿；数据库已提交但重启或验证失败时，必须明确展示“主库已更新、实例待恢复”的状态，提供重试入口，不重复写库，也不得静默隐藏异常。
9. 项目容器遵循会话集合的状态：混合项目由正常会话决定当前账号归属；全部会话归档时项目冻结；取消归档任一会话时项目重新纳入当前账号，但仍归档的其他会话继续保持冻结，不发生会话或消息身份改写。
10. 项目级归档是对现有项目身份及其当前会话的冻结操作；恢复支持“恢复整个项目”和“只恢复选定会话”两种批量意图。只恢复部分会话后，项目进入混合状态，未恢复会话继续归档。归档项目允许创建同名但具有新身份的项目，不自动复用或合并旧项目。
11. 项目合并必须由用户明确选择保留目标，允许归档项目与正常项目互相合并；源项目会话迁入目标项目但保留各自的归档/正常状态、会话身份和消息身份，合并本身不自动取消归档。合并后只要存在正常会话，目标项目就是正常或混合项目；全部会话归档时仍为冻结项目。
12. “冻结”是工具的逻辑分类，不是 TRAE 的项目级只读权限。当前原生通道只有会话级 `chat_session.hidden_status`，工具无法阻止 TRAE 后续向归档项目写入新会话或修改已有内容；这些外部变化不建立精细审计或版本追踪，归档状态保持不变，仍按归档规则展示和排除交接。
13. 项目归档只覆盖提交时已经存在的会话集合。之后 TRAE 在同一项目身份下产生的新会话默认视为正常会话，正常显示并随账号交接；本需求不额外追踪或提示项目内部的外部变化，用户可按需要再次把新会话加入归档变更草稿。工具不得自动隐藏、阻断或遗漏这类新会话。

## 后果

- 归档数量不再增加账号切换的会话级迁移成本，且归档会话不会产生新的身份链或接力记录。
- 多条归档设置共享一次提交边界，避免逐会话写库、关闭和重启实例。
- 工具重启或提交失败不会丢失用户已经编辑的归档变更，但需要提供继续编辑、应用和放弃草稿的明确入口。
- 混合项目不拆分意味着项目容器可随其中的正常会话变更归属，但归档会话本身不发生会话级或消息级改写；取消归档时再把它纳入当前账号的正常范围。
- 需要同时保留交接后的完整性结论与十秒级目标，不能用跳过校验换取表面速度。
- ADR-0022 的归档存储通道仍然有效，后续实现必须保留原生隐藏行为和可逆恢复能力。
- 统一提交的失败路径必须可恢复：提交前失败不改库；提交后恢复失败保留明确的实例恢复状态，不把已提交数据伪装成未提交。
- 项目归档、项目恢复和项目合并都必须进入同一批量草稿与统一提交边界，不能因操作对象从会话变为项目而退回逐条写库。
- 同名项目不代表同一项目；显式合并是唯一改变项目归属关系的入口，并且不以合并为理由静默解冻归档会话。
- 项目冻结不能作为阻止 TRAE 写入的安全边界；本需求不扩展为外部内容审计或版本追踪。
- 项目状态应根据当前会话集合计算：全部归档为归档项目，部分归档为混合项目，存在正常会话即参与当前账号的正常交接。
