# Trae Sync 使用手册

本手册面向 Trae Sync 的日常使用者，按界面逐页说明功能与操作，并解释「主库」的核心概念、数据历史记录同步转移的实现方式与常见问题。

- 适用范围：Windows x64 + TRAE Work CN。本工具为个人自用的非官方产品。
- 构建与运行方法见 [README.md](../README.md)；协议与技术事实见 [TECHNICAL_BASELINE.md](TECHNICAL_BASELINE.md)。

## 界面总览

左侧导航栏有五个页面：**总览、账号、签到、环境、设置**。主库详情页不在导航栏中，从环境页的主库卡进入，页内「返回」回到环境页。

## 总览页

一眼查看当前状态：

- 当前登录主库的账号与主库最近活跃时间。
- 今日签到摘要（统计卡）与快捷操作（去签到、添加账号）。
- 主库统计卡：记录规模概览。

## 签到页

直连签到不走 TRAE 客户端，由工具直接向服务端完成每日签到请求。

- **一键全签**：对全部账号执行签到（状态查询 → 单次领取 → 结果复核）。
- **一键补签**：只对今日未签的账号执行，减少请求量。
- **签到所选**：勾选部分账号后出现，只签所选。
- **行内单签**：每一行的单独签到按钮。
- 批量执行时逐账号错峰进行，进度与结果逐行展示；自动签到批次完成后显示完成横幅。
- 「刷新」按钮只重读本地缓存，不发网络请求。
- 每个账号的结果状态：本次领取成功 / 今日已完成 / 资格未通过（附具体业务原因）/ 登录失效 / 执行异常。业务被拒时文案会给出对应的下一步建议（如等待后重试、重置签到设备、重新登录）。

## 账号页

### 添加账号

1. 点「添加账号」，选择登录浏览器方式：
   - **隔离浏览器**（默认）：独立浏览器实例，与本机已登录状态互不影响。
   - **本机浏览器**：复用本机浏览器默认配置，适合一键授权当前已登录的账号。
2. 在打开的浏览器中完成 TRAE OAuth 授权，工具等待回调（最长约 5 分钟，可随时取消）。
3. 登录成功后凭据自动加密保存；首次登录会引导补录完整手机号（可跳过，用于后续展示与查重）。

同一账号重复登录会覆盖更新档案与凭据。

### 账号列表

- 列表 / 卡片两种视图；可按添加序、名称或签到状态排序；「需处理」过滤只显示异常账号。
- 每个账号展示：显示名称、剩余积分（附缓存时间）、今日签到状态、登录健康度徽章、登录存档状态。
- 主库当前登录账号标记「使用中」；其他账号提供「切换」按钮，点击后进入切号流程（见下文「数据历史记录同步转移的实现」）。
- 批量操作：刷新（纯本地重读）、健康检测（含逐账号真实探测）、刷新额度（只读查询）、刷新全部账号凭据（二次确认后逐账号同设备换发）。

### 账号详情

从列表进入单账号详情：

- 基础信息：显示名称、备注别名、脱敏手机号（可补录或清空）。
- 登录健康度：凭据有效期与状态。
- 操作区：
  - **刷新登录凭据**：同设备换发新令牌，不打开登录页面（二次确认）。
  - **刷新额度**：只读查询剩余积分。
  - **立即签到**：单账号执行一次签到。
  - **重新登录**：走 OAuth 覆盖更新凭据。
  - **重置签到设备**：为账号生成全新虚拟签到设备（二次确认）。
  - **自动签到**：单账号参与自动签到的设置。
  - **删除账号**：二次确认后删除本机档案与凭据。
- 技术细节默认折叠，不占主视野。

## 环境页

环境 = 一个独立的 TRAE 数据目录 + 当前登录的账号。

### 主库卡

置顶显示、默认环境、不可删除，承载主库的生命周期与入口：

- 当前登录账号与实例状态。
- **打开主库详情**（对话列表 / 插件 / 库信息）。
- **主库体检**：账号分布、未注册账号的历史遗留标注、空项目诊断与一键清理（空项目不进入归入范围，可单独清理）。
- **归入当前账号**：在不切号的情况下，把库内不属于当前账号的记录一键归入当前账号；确认后按阶段执行并给出回执。
- **主库自检**：手动触发的四项完整性自检报告。

### 辅助环境

自建的独立数据目录，用于隔离的任务场景：

- 创建环境（命名）、为环境登录账号、启动、重命名、删除（删除需确认）。
- 环境之间可并行运行；每个环境内同时只有一个 TRAE 实例。

## 主库详情页

三个平级标签页：**对话列表**（默认）、**插件**、**库信息**。

### 对话列表

两栏式布局：

- 左栏项目树：项目行原地展开会话子级；顶部搜索；没有名称的项目归并到末尾的「未关联文件夹」组；底部固定区提供「已归档」入口与「选择」按钮。
- 右栏对话查看器：
  - **消息 tab**：聊天流。用户消息按当时的归属账号着色并右对齐，助手消息左对齐；滚到顶部继续加载更早消息。
  - **接力 tab**：会话的转移台账，展示每一段的归属账号、持有时间段与其间新增消息数，当前持有段标记「当前」。
- 列表准实时刷新：TRAE 写入新会话或新消息时自动更新两栏。
- 浏览态下会话行有悬浮快捷归档按钮。

### 归档视图

从底部「已归档」入口进入，与正常列表共用同一棵树、灰显展示（层级：模式 → 项目 → 会话）。归档内容保留在主库中，不参与账号切换交接；在这里可勾选恢复。

### 多选批量操作

点「选择」进入统一选择模式，项目行与会话行都可勾选：

- **归档 / 恢复**：先进入待提交草稿，确认后一次性应用（只产生一次数据库更新与必要的实例关闭、重启）；草稿在工具重启后仍保留，可继续编辑、应用或明确放弃。
- **删除**：真实删除。确认弹层列明会话数与消息量（单次确认），执行前自动创建备份；删除后应用内无法恢复，需要时从备份文件人工找回。
- **合并到…**：至少选择 2 个有名称的项目，指定保留目标后，其余项目的全部会话并入保留项目；每条会话保留原有的归档/正常状态与消息身份。

### 插件

表格化展示已装插件与插件市场，支持分类筛选：

- 每行标注归属：切号保留 / 仅此账号 / 内置 / 已安装。
- **安装**：立即生效（同时更新当前账号云端与环境插件清单），无确认步骤。
- **卸载**：单次确认后从全部账号传播移除。
- 切号时工具会把环境插件清单与目标账号云端自动对账（仅在存在移除差异时于切号弹层中确认）。

### 库信息

主库路径、大小、当前账号、记录统计、最近活跃、最近备份，以及备份对比。

## 设置页

### 自动签到

- 总开关（默认开启）+ 每日时间点；工具运行期间到点自动为未签账号签到，逐账号错峰执行。
- 展示今日自动签到台账（各账号结果）。

### 主库数据备份

- 备份链列表：主库数据文件旁以 `.switch-bak-` 前缀命名的历次备份。
- 手动创建备份：一键复制当前主库数据；主库实例运行中会拒绝并提示。
- 保留策略：自动清理开关 + 保留份数（范围 1-50，默认保留最近 5 份）；超出保留数的旧备份自动删除，关闭自动清理则全部保留。

## 主库概念

### 主库、账号、环境

- **主库**：TRAE 官方数据目录里全部对话记录的集合，同时包含正常会话与已归档会话。它不属于任何一个账号。
- **账号**：登录者身份。记录的归属登记在「当前登录账号」名下，账号只是持有者，不是记录的容器。
- **环境**：一个独立数据目录 + 当前登录账号的组合。主库环境绑定官方目录（默认、不可删除）；辅助环境是自建目录，记录集合互相隔离，任意账号可登录到任意环境。

### 记录归属如何随切号交接

正常会话单一归属当前登录账号。切换账号时，工具把全部正常会话的记录归属与会话身份一并交给新账号——不是复制一份，而是同一套记录换一个持有者。所以任何账号登录主库，看到的都是同一套历史，切号不丢记录。

每段持有历史都会写入转移台账：会话在哪个账号名下、从何时到何时、其间新增多少消息。对话查看器的「接力」tab 就是在看这份台账。

### 归档会话是主库冻结内容

已归档的会话（含整项目归档）从 TRAE 常规列表移出但保留在主库中，属于主库冻结内容：不参与切号交接，归属、会话身份与正文都不改写。只有取消归档后，内容才重新成为当前登录账号的正常会话。混合项目（既有正常又有归档会话的项目）不拆分，由正常会话决定项目是否随切号交接。

### 体检与「归入当前账号」

主库体检是只读健康视图：展示记录在各账号间的分布、标注未注册账号留下的历史遗留、报告空项目等异常。由于历史原因，库里可能存在不属于当前账号的记录；「归入当前账号」在不切号的前提下，把这些记录一键归入当前账号。空项目不进入归入范围，可点「清理空项目」单独清掉（单次确认，执行前自动备份）。

## 数据历史记录同步转移的实现

以切换账号为例（「归入当前账号」复用同一套核心链路）。界面上的切号弹层按六个阶段执行，与后端动作一一对应：

1. **关闭 TRAE 主库实例**：避免运行中的写入与数据库锁冲突；关闭失败则中止，不改库。
2. **备份主库数据**：把主库数据库文件（含 WAL/SHM 伴生文件）完整复制为同目录下 `.switch-bak-{时间戳}` 备份；随后按保留策略自动清理旧备份（默认最近 5 份，可调整或关闭）。备份失败则不执行任何改写。
3. **写入目标账号登录态**：把目标账号的登录材料写入主库数据目录。
4. **转移对话记录到新账号**：在一个数据库事务中改写记录归属与会话身份（含活跃会话的接力处理），随后做完整性校验；任一步失败即整体回滚，库保持原状。同时逐会话写入转移台账，记录转移前后的归属，之后可在「接力」tab 溯源。
5. **同步插件到目标账号**：按环境插件清单与目标账号云端对账并应用（仅在存在移除差异时请求确认）。
6. **重启 TRAE**：恢复实例并验证，给出结果回执。

**失败边界**：任何一步失败都保持原状并明确报错——要么完整转移，要么不转移，不会出现半转移状态。数据库已更新但实例重启失败时，界面明确显示「主库已更新、实例待恢复」并提供重试入口，不重复写库。已归档会话不在转移范围内。

技术细节（数据库结构、会话身份改写、归档冻结边界）见 [TECHNICAL_BASELINE.md](TECHNICAL_BASELINE.md) 与 [ADR-0021](adr/0021-master-single-ownership.md)、[ADR-0022](adr/0022-session-archive-channel.md)、[ADR-0028](adr/0028-archived-session-freeze-boundary.md)。

## 常见问题

**切换账号会丢记录吗？**

不会。主库是所有账号共用的一套记录：切号时正常会话的归属整体交接给新账号，不复制、不删除；已归档会话留在主库原处不动。

**删除会话后还能恢复吗？**

删除是真实删除。执行前有列明规模的二次确认，且工具会先自动创建备份；但应用内不提供撤销。如需找回，从删除前生成的备份文件人工恢复。

**空项目记录是什么？**

没有任何会话的项目记录，多为历史遗留。主库体检会报告数量，它们不进入「归入当前账号」的范围；需要时点「清理空项目」一键清掉（单次确认，执行前自动备份）。

**备份在哪里？**

与主库数据库文件同目录、以 `.switch-bak-` 前缀命名的备份文件。设置页「主库数据备份」可以查看备份链并手动创建；切号与批量删除前也会自动创建。保留策略默认保留最近 5 份，可调整份数或关闭自动清理。
