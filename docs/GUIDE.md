# Trae Sync 使用手册

本手册面向 Trae Sync 的日常使用者，按界面逐页说明功能与操作，并解释「主库」的核心概念、数据历史记录同步转移的实现方式与常见问题。

- 适用范围：Windows x64 + Trae Work CN。本工具为个人自用的非官方产品。
- 构建与运行方法见 [README.md](../README.md)；协议与技术事实见 [TECHNICAL_BASELINE.md](TECHNICAL_BASELINE.md)。

## 界面总览

左侧导航栏有五个页面：**总览、账号、签到、环境、设置**。主库详情页不在导航栏中，从环境页的主库卡进入，页内「返回」回到环境页。

各页面状态徽章使用统一的四色语义：绿色 = 确认正常；灰色 = 中性、无需动作；琥珀色 = 需关注、可自动解决；红色 = 确定性失败、需要人工处理。同一徽章在账号页、签到页与详情页含义一致，一处学会处处适用。

## 总览页

一眼查看当前状态：

- 当前登录主库的账号与主库最近活跃时间。
- 今日签到摘要（统计卡）与快捷操作（去签到、添加账号）。
- 主库统计卡：记录规模概览。

## 账号页

账号页负责账号档案的全部管理：添加账号、查看每个账号的健康状态，以及单账号的日常维护操作。所有账号数据（登录凭据、积分缓存）只保存在本机并经 Windows DPAPI 加密。

### 添加账号

解决什么问题：把 Trae Work CN 账号登录一次、凭据保存进工具，之后签到与切换账号都不需要再手动登录。

1. 在账号页右上角选择登录浏览器方式：
   - **隔离浏览器**（默认）：工具打开一个独立的浏览器实例，与本机浏览器已有的登录状态互不影响，适合登录一个全新账号。
   - **本机浏览器**：复用本机浏览器的默认配置，如果当前浏览器里已经登录了目标账号，选这个可以一键授权。
2. 点「添加账号」，工具会打开 Trae Work CN 登录页并等待授权回调（最长约 5 分钟）。等待期间页面显示进度提示，可随时点「取消登录」；直接关闭浏览器窗口也会同样收尾。
3. 在浏览器中完成 Trae Work CN 的 OAuth 授权后，页面自动继续，提示「账号某某登录成功，已可用于签到」。登录凭据随即加密保存到本机。
4. 首次登录会弹出「补全手机号」窗口（可跳过）：补录完整手机号后，多账号场景下更容易区分账号；之后随时可以在账号详情页补录。已经补录过的账号重复登录时不会再弹出。

同一账号重复登录会覆盖更新档案与凭据，不会产生重复账号。

### 账号列表信息要素

每个账号条目展示的信息（列表与卡片两种视图内容一致）：

- **显示名称**：备注名优先，其次为服务端昵称。
- **签到徽章**：今日签到状态，共六种——「已签」（绿）、「未签」（灰）、「待重试」（琥珀，网络或服务暂时不可用）、「签到失败」（红，被服务端拒绝）、「不可领取」（灰，服务端业务规则拒绝）、「未刷新」（灰空心，今日状态尚未获取，刷新额度后显示）。
- **登录健康度徽章**：登录凭据状态，共五种——「正常」（绿）、「已过期」（琥珀，等待下次签到后自动恢复）、「需重登」（红，凭据失效且无法自动恢复，需重新登录）、「待登录」（琥珀，重新登录一次即可保存）、「未登录」（灰，尚未保存凭据）。
- **模型积分**：真实可用额度（积分包剩余总和），旁注缓存时间；从未查询时显示「未查询」，最近一次刷新失败时额外显示「刷新失败」标记（悬浮可看原因）。
- **手机号**：补录后显示完整号码。
- **登录凭据剩余时间**：如「登录凭据剩余 7 天」；已过期会直接显示「登录凭据已过期」。
- **使用中标记 / 切换按钮**：主库当前登录的账号标记「使用中」；其他账号提供「切换到此账号」按钮，点击后进入切号流程（过程见下文「数据历史记录同步转移的实现」）。

点击任意账号条目进入该账号的详情页。

### 排序、过滤与视图

- **视图**：列表（横向宽行，扫描对比最快）与卡片（网格布局，信息分层展示）两种，右上角分段控件切换，选择会被记住。
- **排序**：按添加顺序、名称或签到状态排序；按签到状态排序时未签账号排在前面，方便优先补签。
- **过滤**：「全部 / 需处理」分段控件；「需处理」只显示异常账号（需重登、已过期、待登录或签到失败），按钮上会标注异常账号数量。

### 批量操作

页头一排按钮面向全部账号：

1. **刷新**：重读本机缓存的账号信息，不发出任何网络请求；新登录、切号之后用它同步显示。
2. **健康检测**：先做本机登录存档深度检测（秒级），再逐账号做只读网络探测，顺带刷新额度。完成后弹出结果卡：首行是正常账号数，下方逐条列出异常账号与一句人话原因（登录问题优先显示）。徽章会同步更新。
3. **刷新额度**：逐账号只读查询最新积分，不消耗签到资格；完成后同样给出结果卡。
4. **刷新凭据**：二次确认后，为全部账号逐个向服务端换发新的登录令牌并更新本机登录信息；期间不会打开新的登录页面。适合在凭据临近过期时统一续期。

### 账号详情

从账号列表点击某个账号进入。详情页自上而下分为：基础信息、登录健康度、自动签到、操作区、危险操作区，最底部是默认折叠的技术细节（账号标识、设备 ID 等，仅排障时展开）。

**基础信息**包括备注名、手机号、模型积分（真实额度）、最近额度刷新、今日签到、添加时间、最近验证与签到设备尾号。其中两项可以直接编辑：

- **备注名**：在输入框中修改后点「保存」即可生效；清空后保存则恢复服务端名称。多账号场景建议给每个账号起一个好认的备注。
- **手机号补录**：输入 11 位完整手机号后点「保存」。如果服务端记录过脱敏号，输入必须与其首尾号段一致；若该手机号已被其他账号使用，会弹出确认层说明情况，确认后仍可保存。清空后保存则恢复显示脱敏号。

**登录健康度**展示访问令牌（access）与刷新令牌（refresh）各自的剩余天数和具体到期时刻。应用会按需自动维护凭据；若账号仍在使用旧版登录通道，页面会给出提示：可先尝试「刷新登录凭据」，无效再重新登录。

**操作区**的按钮与用途：

- **刷新登录凭据**：同设备向服务端换发新令牌，不打开登录页面（需二次确认）。成功后提示「登录凭据已更新，无需重新登录」。
- **刷新额度**：只读查询该账号的剩余积分，完成后显示最新额度与今日签到状态。
- **立即签到**：为该账号单独执行一次签到；今日已签时按钮自动禁用并显示「今日已签到」。
- **重新登录**：走一次浏览器 OAuth 流程覆盖更新凭据，适合凭据已失效且无法换发的情况。
- **重置签到设备**：为账号生成全新的虚拟签到设备并更新登录信息（需二次确认）。当签到连续多日被服务端以设备原因拒绝（界面提示 9074/9095）时使用。

**危险操作区**：

- **删除账号**：单次确认后删除本机的账号档案、加密登录凭据与积分缓存。不影响其他账号与主库历史数据；删除后如需恢复，用该账号重新登录即可。

**自动签到**：单账号的参与开关。开启后该账号加入每日自动签到批次；关闭后不参与自动批次，但仍可手动签到。

## 签到页

签到页解决「每天逐个打开客户端手动签到」的问题：工具不走 Trae Work CN 客户端，直接向服务端完成每日签到请求，多个账号一键处理。

### 手动签到

签到账号列表中每个账号一行，行首是勾选框，行尾是行内单签按钮。四个签到入口的区别与适用场景：

- **一键全签**：对全部账号执行签到，已签账号自动跳过（只多一次状态查询）。适合每天第一次打开工具时使用，一次确保所有账号都签完。
- **一键补签**：只对今日尚未签到的账号执行，请求量最小。适合全签过一轮之后又有账号失败、或只想处理漏签账号的场景；对减少服务端请求、降低风控触发面更友好。
- **签到所选**：勾选部分账号后出现（勾选数少于总数时显示），只签所选账号。适合只处理个别账号。
- **行内单签**：每一行右侧的「签到」按钮，仅对该账号执行；今日已签的账号按钮禁用。

操作流程：

1. 进入签到页，工具自动读取全部账号的今日签到状态与缓存额度。
2. 按需点「一键全签」「一键补签」「签到所选」或行内「签到」。
3. 批量执行时逐账号串行进行：每个账号走「状态查询 → 单次领取 → 结果复核」，账号之间随机间隔 3-8 秒（行内显示「N 秒后开始」倒计时）；顶部进度条显示 X/Y 总进度。
4. 执行期间可点「取消未开始任务」，尚未执行的账号不再继续；已完成的账号结果保留。
5. 每个账号的结果直接落在该行行尾；批量结束后顶部给出汇总消息（全部完成或「部分签到未完成，请查看逐账号结果」）。

页头的「刷新」按钮只重读本机缓存的账号信息，不发网络请求；要更新积分与签到状态请执行签到或到账号页刷新额度。

### 签到结果状态含义

每个账号执行后的结果文案与含义：

- **签到成功**：服务端已确认领取，奖励已发放。
- **今日已签到**：服务端确认该账号今日已签过，无需重复领取。
- **当前不可领取**：服务端业务规则判定该账号当前不符合领取条件。
- **结果待复核**：签到请求已发出但结果未能即时确认，稍后刷新可确认实际状态。
- **网络错误 / 账号忙**：传输性失败，稍后重试即可。
- **登录已失效（20324），请重新登录 / 登录材料缺失或无效，请重新登录**：凭据问题，需到账号页重新登录或刷新凭据。
- **设备信息未获服务端信任（9074），可在账号详情重置签到设备**：签到设备未获信任，到账号详情执行「重置签到设备」。
- **该设备今日名额已用（9095），明日再试**：该签到设备今日额度已用完，次日自动恢复。
- **设备刚创建，请等待约 5 分钟后重试**：新设备需要等待服务端放行。
- **服务端拒绝（数值）**：其他业务拒绝，界面会原样透出服务端原因码，便于排障。

列表中未执行签到的账号行也会常驻显示今日状态徽章（已签 / 未签 / 签到失败 / 待重试 / 不可领取 / 未刷新），含义与账号页一致。

### 自动签到

自动签到解决「忘记手动签到」的问题：工具运行期间到点自动为参与的账号完成签到。

- **总开关与触发时间**：在「设置」页的「自动签到」分区开启，并设定每日触发时间（默认开启）。开启后工具运行期间每天到点自动执行。
- **错峰与补偿**：到点后各账号在 0-15 分钟内随机错峰执行，避免同一时刻集中请求；如果到点时工具没有运行，迟于设定时间打开应用会自动补偿执行一次。
- **账号参与开关**：在账号详情页的「自动签到」分区可为单个账号选择参与或不参与；关闭后该账号仍可手动签到。
- **执行反馈**：签到页顶部常驻显示自动签到状态行（「每日 HH:MM 触发」及今日台账）；批次完成后显示完成横幅（成功 X/Y、失败、跳过数量），并逐行列出各账号结果。设置页同样展示今日台账。

## 环境页

环境页解决「多个数据目录、多个登录身份如何组织」的问题。**环境 = 一个独立的 Trae Work CN 数据目录 + 当前登录的账号**。

- **主库**：绑定 Trae Work CN 官方数据目录的默认环境，不可删除。你的全部对话记录都在主库里，所有账号共用；在「账号」页切换账号，记录全部保留。
- **辅助环境**：自建的独立数据目录，与主库并行使用、记录互相隔离，适合隔离的任务场景。
- **当前登录账号**：主库不属于任何一个账号，每条记录的归属登记在「当前登录账号」名下；切换账号时记录归属整体交接（详见「主库概念」）。环境卡上显示的「当前登录」就是这个名字。

### 主库卡

置顶显示、默认环境、不可删除，承载主库的生命周期与入口：

- **状态徽章**：实例与登录状态合一，常见有「未启动」「登录有效」「待登录」「登录失效」「运行中」「运行中 · 已登录」「运行中 · 待登录」「运行中 · 登录失效」。琥珀色状态表示需要处理：未登录时按提示完成一次登录即可注入登录态。
- **当前登录账号**：卡片右侧显示头像与账号名。
- **启动主库 / 聚焦主库**：未运行时点「启动主库」拉起 Trae Work CN 实例；已在运行时按钮变为「聚焦主库」，把既有窗口带到前台。
- **数据目录**：卡片左下角入口，悬浮显示完整目录路径。

主库尚未登录账号时，卡片会提示：首次启动后请在 Trae Work CN 窗口内登录一次，此后切换账号全自动完成。

### 主库体检

体检解决「历史遗留记录无人认领」的问题：库里可能存在登记在其他账号名下、不随当前账号展示的记录。体检区块只在发现这类记录时出现，平时不打扰。

各项读法：

- **「有 N 个账号的 M 个会话在主库中，未随当前账号展示」**：说明有 M 个会话归属登记在其他账号名下。下方逐行列出这些账号（未登记过的显示「未登记账号」）及其会话数、项目数。
- **「另有 K 个空项目记录未进入归入范围」**：空项目是不含任何会话的项目记录，多为历史遗留；它们不参与「一键归入」，需要单独清理。下方列出对应账号与空项目数量。
- **「另有 N 条无归属记录不会被归入」**：无法判定归属的记录，归入操作不会触碰它们。

### 一键归入当前账号

解决「不切换账号也要把遗留记录收拢到当前账号」的问题：

1. 在体检区块点「一键归入当前账号」。
2. 弹层列明规模：将归入的账号列表、会话与项目总数，并提示主库会自动关闭并重启、归入前会创建数据备份；无归属记录不会归入。
3. 点「确认归入」，弹层按四个阶段展示进度：关闭主库 → 创建备份 → 归入记录 → 重启主库。
4. 完成后给出回执（归入的账号数、保留项目数、转移会话数）；任何一步失败都会保持原状并明确报错，不会出现半归入状态。

### 清理空项目

解决「历史遗留的空项目记录占着体检报告」的问题：

1. 在体检区块点「清理空项目」。
2. 确认弹层列明将删除的空项目数量，并说明：删除前会自动备份；空项目记录不含任何对话，删除不影响对话历史；无归属记录不会被清理。
3. 确认后执行（主库会自动关闭再重启），完成后提示「已删除 N 个空项目记录（已自动备份）」；若主库未能自动重启，按提示从环境页重新打开即可。

### 主库自检

解决「切号前后主库状态是否健康」的确认问题。点主库卡右下角「自检」，工具做只读检查并给出四项报告：**读校验**（数据库能否正常读取）、**一致性**（记录归属是否自洽）、**可切换**（是否满足切号条件）、**深度检查**（结论收在「查看深度检查说明」折叠区）。每项标注「正常 / 需关注 / 需人工 / 暂不可用」，整体级别为「健康 / 可自愈 / 需人工处理」。

如果实际登录账号与工具记录不一致，报告会同时列出两个名字，并提供「纠正为实际登录账号」按钮；点击后工具按实际登录账号纠正记录并重新自检。自检只读不写库，纠正操作除外。

### 辅助环境

辅助环境用于隔离场景：独立的 Trae Work CN 数据目录，环境之间可并行运行，每个环境内同时只有一个 Trae Work CN 实例。

1. **创建**：点辅助环境区右上角「新建环境」，输入名称（1-64 个字符）后确认，新环境卡片随即出现。
2. **登录账号**：在环境卡上点「登录账号」，从已保存账号中选择一个确认。环境内的对话记录会随登录归到所选账号名下；首次登录会直接完成初始化，之后显示转移的项目与会话数量。
3. **启动 / 聚焦**：点「启动」拉起该环境的 Trae Work CN 实例；已在运行时变为「聚焦」。
4. **重命名**：点「重命名」输入新名称保存。
5. **删除**：点「删除」，确认弹层会先读取并列明该环境的数据规模（项目数、会话数与体积）——删除后无法恢复，确认后才执行。从未启动的环境没有对话数据，仅删除环境目录。

## 主库详情页

主库详情页提供主库内容的日常浏览与管理入口。从环境页主库卡的「详情」按钮进入，页内左上角「返回」回到环境页。页面分三个平级标签：**对话列表**（默认）、**插件**、**库信息**。

### 对话列表

两栏式布局，解决「不打开客户端也能查看与管理全部对话」的问题：

- **左栏项目树**：
  - 项目行原地展开会话子级；顶部搜索框按会话标题过滤。
  - 没有名称的项目归并到树末尾的「未关联文件夹」组，避免一堆同名空文件夹。
  - 底部固定区提供「已归档」入口（有归档内容才显示）与「选择」按钮。
- **右栏对话查看器**（从左栏选中会话后显示）：
  - **消息 tab**：聊天流。用户消息按当时的归属账号着色并右对齐，助手消息左对齐；滚到顶部继续加载更早消息。
  - **接力 tab**：该会话的转移台账，展示每一段的归属账号、持有时间段与其间新增消息数，当前持有段标记「当前」。
- **准实时刷新**：Trae Work CN 写入新会话或新消息时，两栏自动更新。
- 浏览态下会话行悬浮会出现快捷归档按钮，单击即可归档单个会话。

### 归档视图

归档解决「会话太多想收起来但不想删」的问题：把会话或整个项目移出常规列表，内容仍完整保留在主库中。

1. 在对话列表底部点「已归档」进入归档视图；它与正常列表共用同一棵项目树，灰显展示（层级：模式 → 项目 → 会话）。
2. 归档内容不参与账号切换交接，归属与正文都不改写；在这里勾选会话后可执行「恢复」，把它们放回常规列表。
3. 没有归档内容时视图会提示「没有已归档的会话」。

### 多选批量操作

批量操作解决「逐个处理太慢」的问题。点左栏底部「选择」进入统一选择模式，项目行与会话行都可勾选（项目勾选会覆盖其下全部子会话）；底部浮出操作栏，按 Esc 可退出选择模式。

- **归档 / 恢复**：勾选后先进入待提交草稿（底部显示「待提交：归档 N 个 · 恢复 M 个」），确认「应用归档设置」后一次性生效——只产生一次数据库更新与必要的实例关闭、重启。草稿在工具重启后仍保留，可继续编辑、应用或明确放弃。
- **删除**：真实删除。确认弹层列明会话数与消息量（单次确认），执行前自动创建备份；删除后应用内无法恢复，需要时从备份文件人工找回。
- **合并到…**：至少选择 2 个有名称的项目后可用。指定保留目标后，其余项目的全部会话并入保留项目，每条会话保留原有的归档/正常状态与消息身份；合并前会自动备份，误合并可用备份人工恢复；被移空的项目随之清理。

### 插件

插件 tab 解决「多账号插件清单不一致」的管理问题。表格化展示已装插件与插件市场，顶部分类筛选，市场段支持搜索：

- 每行标注归属：**切号保留**（属于环境、切号不动）/ **仅此账号**（绑定当前账号）/ **内置** / **已安装**。
- **安装**：点「安装」立即生效，同时更新当前账号云端与环境插件清单；无确认步骤。
- **卸载**：单次确认后从全部账号传播移除。
- 切号时工具会把环境插件清单与目标账号云端自动对账（仅在存在移除差异时于切号弹层中确认）。

### 库信息

库信息 tab 是主库的「档案页」：当前账号、主库大小、最近活跃、最近备份、主库路径（完整路径收在悬浮提示中），以及当前账号可见的项目 / 会话 / 消息数量统计，并提供备份对比查看。

## 设置页

### 自动签到

- 总开关（默认开启）+ 每日时间点；工具运行期间到点自动为未签账号签到，逐账号错峰执行。
- 展示今日自动签到台账（各账号结果）。
- 错峰与补偿的详细行为、单账号参与开关见「签到页」的「自动签到」小节。

### 主库数据备份

解决「改库操作出错时有退路」的问题：

- **备份链列表**：主库数据文件旁以 `.switch-bak-` 前缀命名的历次备份，逐条显示时间、大小与类型（完整快照 / 含附属件）。
- **手动创建备份**：点「立即备份」一键复制当前主库数据；主库实例运行中会拒绝并提示，先关闭主库再备份。
- **保留策略**：自动清理开关 + 保留份数（范围 1-50，默认保留最近 5 份）；超出保留数的旧备份会在新备份生成后自动删除，关闭自动清理则全部保留。
- **恢复指引**：展开「查看备份位置与恢复步骤」可看到备份所在目录与人工恢复步骤：先关闭 Trae Work CN，再把所选备份内的文件复制回该目录覆盖原位，然后重新启动。

## 主库概念

### 主库、账号、环境

- **主库**：Trae Work CN 官方数据目录里全部对话记录的集合，同时包含正常会话与已归档会话。它不属于任何一个账号。
- **账号**：登录者身份。记录的归属登记在「当前登录账号」名下，账号只是持有者，不是记录的容器。
- **环境**：一个独立数据目录 + 当前登录账号的组合。主库环境绑定官方目录（默认、不可删除）；辅助环境是自建目录，记录集合互相隔离，任意账号可登录到任意环境。

### 记录归属如何随切号交接

正常会话单一归属当前登录账号。切换账号时，工具把全部正常会话的记录归属与会话身份一并交给新账号——不是复制一份，而是同一套记录换一个持有者。所以任何账号登录主库，看到的都是同一套历史，切号不丢记录。

每段持有历史都会写入转移台账：会话在哪个账号名下、从何时到何时、其间新增多少消息。对话查看器的「接力」tab 就是在看这份台账。

### 归档会话是主库冻结内容

已归档的会话（含整项目归档）从 Trae Work CN 常规列表移出但保留在主库中，属于主库冻结内容：不参与切号交接，归属、会话身份与正文都不改写。只有取消归档后，内容才重新成为当前登录账号的正常会话。混合项目（既有正常又有归档会话的项目）不拆分，由正常会话决定项目是否随切号交接。

### 体检与「归入当前账号」

主库体检是只读健康视图：展示记录在各账号间的分布、标注未注册账号留下的历史遗留、报告空项目等异常。由于历史原因，库里可能存在不属于当前账号的记录；「归入当前账号」在不切号的前提下，把这些记录一键归入当前账号。空项目不进入归入范围，可点「清理空项目」单独清掉（单次确认，执行前自动备份）。

## 数据历史记录同步转移的实现

以切换账号为例（「归入当前账号」复用同一套核心链路）。界面上的切号弹层按六个阶段执行，与后端动作一一对应：

1. **关闭 Trae Work CN 主库实例**：避免运行中的写入与数据库锁冲突；关闭失败则中止，不改库。
2. **备份主库数据**：把主库数据库文件（含 WAL/SHM 伴生文件）完整复制为同目录下 `.switch-bak-{时间戳}` 备份；随后按保留策略自动清理旧备份（默认最近 5 份，可调整或关闭）。备份失败则不执行任何改写。
3. **写入目标账号登录态**：把目标账号的登录材料写入主库数据目录。
4. **转移对话记录到新账号**：在一个数据库事务中改写记录归属与会话身份（含活跃会话的接力处理），随后做完整性校验；任一步失败即整体回滚，库保持原状。同时逐会话写入转移台账，记录转移前后的归属，之后可在「接力」tab 溯源。
5. **同步插件到目标账号**：按环境插件清单与目标账号云端对账并应用（仅在存在移除差异时请求确认）。
6. **重启 Trae Work CN**：恢复实例并验证，给出结果回执。

**失败边界**：任何一步失败都保持原状并明确报错——要么完整转移，要么不转移，不会出现半转移状态。数据库已更新但实例重启失败时，界面明确显示「主库已更新、实例待恢复」并提供重试入口，不重复写库。已归档会话不在转移范围内。

技术细节（数据库结构、会话身份改写、归档冻结边界）见 [TECHNICAL_BASELINE.md](TECHNICAL_BASELINE.md) 与 [ADR-0021](adr/0021-master-single-ownership.md)、[ADR-0022](adr/0022-session-archive-channel.md)、[ADR-0028](adr/0028-archived-session-freeze-boundary.md)。

## 常见问题

**切换账号会丢记录吗？**

不会。主库是所有账号共用的一套记录：切号时正常会话的归属整体交接给新账号，不复制、不删除；已归档会话留在主库原处不动。

**删除会话后还能恢复吗？**

删除是真实删除。执行前有列明规模的二次确认，且工具会先自动创建备份；但应用内不提供撤销。如需找回，从删除前生成的备份文件人工恢复。批量删除与合并等改写主库数据的操作都存在数据风险，请在操作前确认备份可用。

**空项目记录是什么？**

没有任何会话的项目记录，多为历史遗留。主库体检会报告数量，它们不进入「归入当前账号」的范围；需要时点「清理空项目」一键清掉（单次确认，执行前自动备份）。

**备份在哪里？**

与主库数据库文件同目录、以 `.switch-bak-` 前缀命名的备份文件。设置页「主库数据备份」可以查看备份链并手动创建；切号与批量删除前也会自动创建。保留策略默认保留最近 5 份，可调整份数或关闭自动清理。人工恢复步骤见设置页备份分区的「查看备份位置与恢复步骤」。
