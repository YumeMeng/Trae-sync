# Spec：Phase 16 —— 账号捕获闭环 + 备份治理 + 移植性纪律

> 来源：2026-10-16 grilling 共识（12 项决策，Q1-Q12 全部落定）。术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## Problem Statement

工具的账号池是封闭的：16 个迁移账号之外，任何**新登录的 TRAE 账号**（新注册/新购入）都无法进入工具体系——不能切号、不能自动签到。根因是登录入库链路指向已废弃语义的旧池根（`products/trae_cn`），与账号页的实际读取源（checkin 根 + .fused 容器）脱节。

同时，主库备份链（每份 1.6GB，未压缩）寄生在**客户端目录内**（C 盘），随写操作线性增长——C 盘已两次爆满，备份是尚未治理的最后一个大占用项。

面向未来：同类能力将适配到 WorkBuddy 工具。当前代码的产品差异散落在 5+ 层（109 处 TraeProduct 引用、4 处独立存储根派生、37 处防逃逸判定点未统一），移植需要先收敛。

## Solution

1. **账号捕获**：环境页新增「从客户端捕获账号」——读取 Trae 客户端登录 blob，在线复核身份，按批量铸造同链路铸造 .fused 容器 + .checkin 凭据包，Work 档案登记入池（**入池即全功能**：切号/签到/历史全覆盖）。
2. **备份治理三合一**：默认备份目录迁软件本体旁（E 盘）+ 三件套备份 zstd 压缩（体积减 75%）+ 现有备份链迁移转换（C 盘释放 3.13GB）。
3. **移植性纪律**：存储根派生收口单一来源；37 处防逃逸判定点统一走 link_guard；并发锁对瞬时拒绝加退避重试；测试 fixture 目录收敛清理。WorkBuddy 立项时的系统性 product descriptor 抽象**显式延迟**到那时再做（协议细节未调研，现在抽象是空想）。

## User Stories

1. 作为工具用户，我想在 Trae 客户端登录一个新账号后，点击「从客户端捕获账号」把它收入账号池，这样不需要任何手动凭据操作。
2. 作为工具用户，我想在捕获时看到账号身份（昵称/账号 ID）的在线复核结果，这样确认收进来的是正确的账号。
3. 作为工具用户，我想让已入池的账号再次捕获时得到明确提示（已存在），这样不会产生重复档案。
4. 作为工具用户，我想让新捕获的账号立即支持自动签到，这样它与其他 16 个账号能力完全一致。
5. 作为工具用户，我想让新捕获的账号立即支持切号（作为切出/切入目标），这样账号池是完整可用的。
6. 作为工具用户，我想让主库备份自动存放到软件本体旁的 backups 目录并压缩，这样 C 盘和客户端目录都不再被备份占用。
7. 作为工具用户，我想让既有备份链在升级后自动迁移转换，这样升级过程零手工。
8. 作为工具用户，我想让恢复（切号回滚/手动恢复）对压缩备份透明，这样备份格式变化不影响恢复可靠性。
9. 作为工具用户，我想让并发场景下的锁获取对瞬时拒绝自动重试一次，这样偶发的环境抖动不报错。
10. 作为工具用户，我想让测试产生的临时目录不再残留累积，这样长期使用 TEMP 不膨胀。
11. 作为工具维护者，我想让防逃逸判定只有 link_guard 一个入口，这样未来适配新产品时判定逻辑只改一处。
12. 作为工具维护者，我想让存储根派生只有一个来源，这样移植新产品时路径规则只改一处。
13. 作为工具维护者，我想让 WorkBuddy 适配时能复用捕获/铸造/备份/闸门的全部编排，所以本轮新代码不把 Trae 特定逻辑写进公共路径。

## Implementation Decisions（grilling 共识 Q1-Q12）

- **捕获路线**（Q3）：从客户端 blob 捕获（非 OAuth 浏览器流程）。新编排：读登录 blob → 在线 GetUserInfo 复核 → GetPCAuthCode → ExchangeToken（设备身份对齐，P15-0 同链路）→ FusedLoginStore.save（.fused）+ CheckinCredentialStore 写入（.checkin，Q10）→ AccountRegistry 档案登记 → 可选选择指针提交。
- **去重**（Q3）：user_id 已在 AccountRegistry → 拒绝（`account_already_registered`），无副作用。
- **旧 OAuth 链处置**（Q4）：`complete_trae_cn_login`/`begin_trae_cn_login` 暂保留不动（无实际消费方受损），捕获路线稳定后标记 deprecated 并评估前端入口移除。
- **验收**（Q5）：无新号——mock + 隔离演练验收（隔离目录 + 真实代码路径，fused_switch 同模式）；真号到位后补单次确认真机验收。
- **备份**（Q11/Q12）：默认目录 = 软件本体旁 `backups/`（exe 同级推导）；zstd 压缩（.zst）；恢复/迁移双格式兼容（旧未压缩 + 新压缩）；现有 4 份迁移转换后原副本删除。
- **移植策略**（Q2）：纪律 + 延迟抽象（方案 C）。新代码产品参数化；存储根收口与判定点统一是本轮两个落地点。
- **37 处判定点**（Q1）：expand（link_guard）已落，本轮做 contract（批量替换调用点），机械替换。
- **停服**（Q6）：清单停服前 1-2 天出，本轮不含。

## Testing Seams

- **主缝（唯一新缝）**：`capture` 编排函数——与 switch_master_account_at 同构的「输入账号材料 → 副作用（容器/档案/指针）→ 回执」形态，离线测试注入临时目录与 mock HTTP（既有 fused_switch/隔离演练模式）。
- **备份压缩**：既有 backup_master_trio_to / 恢复链的单测扩展（压缩写/双格式读/迁移幂等）。
- **判定点统一**：既有 storage_root 等模块单测全量回归（调用点替换不改语义）。
- **锁重试**：error 5 注入单测（observe 注入模式）。
- **真机补验**（后置）：新号真实登录 → 捕获 → 客户端/工具双侧核对。
